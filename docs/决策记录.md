## D-01 文本模型选用火山引擎豆包 API

- 日期：2026-08-16
- 状态：已生效
- 决策：所有文本生成（热点解读、文案、脚本、直播话术）统一调用火山引擎方舟平台的豆包大模型 API。
- 理由：中文和乡土口语表达质量好的同时价格低、国内访问稳定，适合预算有限的基层公益项目。

## D-02 图像生成选用 Seedream

- 日期：2026-08-16
- 状态：已生效
- 决策：海报背景图等图像生成任务使用字节 Seedream 图像模型（同样经火山引擎接入）。
- 理由：与豆包同属火山引擎平台，一套密钥和计费即可同时覆盖文本与图像，降低接入与运维成本。

## D-03 热榜数据源采用 DailyHotApi

- 日期：2026-08-16
- 状态：已生效
- 决策：热点雷达的各平台热榜数据通过 DailyHotApi（聚合微博、抖音、百度等热榜的开源 API）获取，服务端缓存后做筛选。
- 理由：免维护地一次接入多个平台热榜，避免逐家对接和爬虫被封的风险。

## D-04 海报采用"模板 + AI 背景图 + 程序渲染文字"

- 日期：2026-08-16
- 状态：已生效
- 决策：物料工坊不让 AI 直接生成带文字的完整海报，而是预制版式模板，AI 只生成背景图，产品名、价格、电话等文字由程序渲染叠加。
- 理由：AI 直出海报的中文字经常写错，而价格和电话错一个字就是事故，程序渲染文字可保证 100% 准确。

## D-05 Skill 通过 system prompt 注入方式移植

- 日期：2026-08-16
- 状态：已生效
- 决策：skills/ 目录下的技能包（符合 Anthropic Agent Skills 规范）不在服务端运行 Agent 框架，而是在调用豆包 API 时将 skill 内容注入 system prompt 实现同等效果。
- 理由：豆包 API 不支持 Anthropic 原生 skill 机制，注入 system prompt 是最低成本、无额外依赖的等效方案。

## D-06 测试记录按 skill 分文件管理

- 日期：2026-08-17
- 状态：已生效
- 决策：skill 测试结果不再统一写入 docs/测试记录.md，改为 docs/测试记录/<skill名>.md 一 skill 一文件（test_skill.py 根据 --skill 参数自动取文件夹名）；每轮以「## 第N轮 | 日期时间 | 模型名」为分隔标题，轮次号自动递增。
- 理由：4 个 skill 陆续进入迭代，混在一个文件里难以做同 skill 的跨轮对比；分文件后每个 skill 的演进历史独立可读，互不污染。

## D-07 物料工坊网页需有功能引导 UI（产品需求备忘）

- 日期：2026-08-17
- 状态：待实施（阶段 3 网站开发时执行）
- 决策：阶段 3 做网站时，物料工坊页面必须有功能引导——在输入框 placeholder 或欢迎语中展示三个功能入口：①写文案（朋友圈/社群/视频号）②做海报 ③检查或改写文案违禁词。
- 理由：promo-materials skill 的"开场引导"规则在聊天形态下由模型输出菜单，在网页形态下应由 UI 承接，不能依赖用户自己摸清功能边界；50-70 岁用户需要"看得见、点得到"的入口。

## D-08 聊天接口改用 SSE 流式输出

- 日期：2026-08-28
- 状态：已生效
- 决策：/api/chat 从一次性 JSON 响应改为 SSE 流式（delta 事件逐字上屏 → 海报管线 → done 事件带海报结果），mock 演示模式按字符切片模拟流式；调用超时从 120s 调整为 300s。
- 理由：doubao-seed-evolving 带完整知识库首 token 实测需 116~131 秒，非流式下用户干等且 120s 超时误杀正常请求；流式让等待过程可见，海报依赖完整文本的架构不变。

## D-09 海报模板 T01/T02/T03 三套版式落地于程序渲染层

- 日期：2026-08-28
- 状态：已生效
- 决策：三模板版式直接实现在 scripts/render_poster.py（T01 顶部标题带+底部信息带 / T02 居中大标题+中部卖点 / T03 左侧文字栏+右侧留图），不另建 assets/templates/ 版式定义文件；字体路径通过 POSTER_FONT 环境变量配置并自动探测系统中文字体。
- 理由：模板只是排版参数差异，代码实现比外部模板文件更简单可维护；字体配置化保证 Windows 开发与 Linux 部署都能跑。
